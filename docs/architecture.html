Factory Inventory Management System

Architecture overview: system layout, technology stack, and data flow

Executive Summary

A full-stack demo application with no database.

A Vue 3 single-page application (port 3000) calls a FastAPI REST service (port 8001). The API serves data loaded once at startup from static JSON files into memory, filters it per request, and validates responses with Pydantic. Four global filters (time period, warehouse, category, order status) drive every view.

Data Flow

What happens when a user changes a filter.

  1. User changes a filterFilterBar updates shared refs in useFilters (singleton state).
  2. View reactsWatchers call getCurrentFilters(), which maps the period to a month parameter.
  3. API client builds the requestapi.js omits filters set to all and sends the rest as query params.
  4. FastAPI filters in memoryapply_filters and filter_by_month narrow the lists loaded from JSON.
  1. Aggregate and validateEndpoints compute totals and Pydantic validates the response model.
  2. JSON returnedCORS is open to all origins for local development.
  3. State updatedRaw data lands in refs such as allOrders and inventoryItems.
  4. UI re-rendersComputed properties derive chart and table data from the refs.

Design Notes and Constraints

Stateless and resettable

  • Restarting the API reloads the JSON files.
  • No persistence layer or migrations.

Filter limits

  • Inventory has no time dimension, so it ignores the month filter.
  • Demand, backlog, spending, and reports are unfiltered.

Keep in sync

  • Update Pydantic models when the JSON structure changes.
  • The API base URL is hardcoded in api.js.
